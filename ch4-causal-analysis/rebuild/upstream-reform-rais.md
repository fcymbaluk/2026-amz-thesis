# Chapter 4 — upstream reform list: RAIS re-extraction (BigQuery)

General BigQuery rules (billing, caps, dataset permissions, query discipline) are in `docs/bigquery.md` at the repository root; this brief's task-specific rules build on them.

Context for the agent: Chapter 4 studies how social conditions and social policy relate to deforestation in the Brazilian Amazon at the municipal level. The labor-market variables in `final_dataset_6.csv` come from a RAIS extraction that kept occupation and six wage brackets and discarded everything else at the aggregation step. Three kinds of information were lost: the wage distribution beyond the brackets, the employer's sector and legal nature, and sectoral employment counts. This reform reopens the extraction so the panel carries a richer set of labor-market variables that later analysis can use in whatever form it needs. The reform builds data, not models: no indicator here is tied to a particular estimator or specification, and no estimation happens in this task. Work through the three tasks in order after the decisions in section 0 are confirmed with me. Debate design before writing SQL, run dry-run cost estimates before executing, and warn me about problems as you find them.

## Current pipeline (do not break it)

- Source: `basedosdados.br_me_rais.microdados_vinculos` (Base dos Dados, update 2025-08-26; cleaning per rdahis/clean_RAIS).
- Query 1 filters to the 9 Legal Amazon states (AC, AM, AP, MA, MT, PA, RO, RR, TO), 1999–2024, `vinculo_ativo_3112 = '1'`, positive `valor_remuneracao_media`; builds `cbo_unified` (CBO-2002 six digits, or CBO-1994 five digits plus a trailing zero); joins the IPCA deflator (`amz-data-dissertation.social_employment_1.deflator_ipca_2024`) and writes `amz-data-dissertation.social_employment_1.rais_vinculos_deflat`.
- Query 2 aggregates that table by `year × geocode × workers_agricultural (CBO first digit = 6) × wage_code` (six brackets against the fixed 2024 minimum wage, R$ 1,412) and counts workers. The output is read by script 02 as `_data/data_employment_rais`, normalized by interpolated PIA, and becomes `emp_pia_rate_*` and `emp_share_*` in the panel.
- What the intermediate table keeps: occupation (CBO), deflated wage. What it does not keep: sector (CNAE), employer legal nature (`natureza_juridica`), the raw wage distribution beyond the six brackets.

Regression rule for the whole reform: after any change to Query 1, re-run Query 2 unchanged and confirm that the resulting `workers_total` by `year × geocode × workers_agricultural × wage_code` matches the current `_data/data_employment_rais` exactly. The existing variables must not move.

## Route decision: BigQuery (Route A) is the default; raw rebuild (Route B) is the fallback

The agent works on Route A unless Route A is blocked. Reasons, in order of weight:

1. **Harmonization is already done.** Base dos Dados (`rdahis/clean_RAIS`) has harmonized the RAIS layouts across 1985–2024: column names and positions change several times, encodings are Latin-1, CNAE 1.0/2.0 and CBO-1994/2002 coexist, and the municipality code needs a 6-to-7-digit fix in early years. Every variable this reform needs (`cnae_1`, `cnae_2`, `cnae_2_subclasse`, `natureza_juridica`, `valor_remuneracao_media`, `valor_remuneracao_dezembro`) is already a clean column in `microdados_vinculos`. Rebuilding from the raw files means redoing that harmonization, and any mistake would put the new variables on a different footing from the existing ones, which came from the BD table.
2. **The existing variables are BD-derived.** The regression rule above only works if the new extraction reads the same source. A raw rebuild would have to reproduce `emp_share_low_workers` exactly before any new variable is trusted, which is a validation project on its own.
3. **Scale.** The raw public microdata run to hundreds of gigabytes across all years, compressed .7z, one file per state (later per region) and year, served by the MTE FTP (`ftp.mtps.gov.br/pdet/microdados/RAIS/`). FTP access is intermittent and blocked on some networks. An agent can script the download, but it cannot make the server reliable. BigQuery scans the 9-state slice with the needed columns in minutes.
4. **Cost is not the constraint.** The table is partitioned by year and clustered by state and municipality, so a filtered query over 9 states and 26 years reads a fraction of the table. GCP gives 1 TB of query processing per month at no charge; the whole reform fits inside that if the agent runs dry runs first and avoids `SELECT *`. The project `amz-data-dissertation` and its billing already exist.

**Hybrid workflow (recommended within Route A).** Do not iterate on BigQuery. Run the rebuilt Query 1 once, write the lean vínculo-level table (year, geocode, cbo_unified, cnae_1, cnae_2, natureza_juridica, nominal wage, deflated wage) to a GCS bucket as Parquet, download it, and do every aggregation (Queries 2, 3, 4 and all diagnostics) locally with DuckDB from R (`duckdb` + `dbplyr`) or `arrow`. Expected size for 9 states × 26 years is on the order of tens of gigabytes uncompressed, single-digit gigabytes in Parquet, which a laptop handles. This gives reproducible local scripts, no repeated cloud cost, and a frozen snapshot of the source with its BD update date recorded. Keep the SQL for Queries 2–4 as DuckDB SQL in the R script so the pipeline reads as one document.

**Agent setup for Route A.** See the section "Direct access to the BigQuery project" below. In short: Fernando authenticates once in the environment where the agent runs; the agent inherits the session through the `gcloud`/`bq` CLIs and the `basedosdados`/`bigrquery` R packages, works only in a new dataset, and runs every query with a byte cap.

**4. Cost guard.** Every query is dry-run first (`bq query --dry_run` or `bigrquery::bq_perform_query(..., dry_run = TRUE)`) and the bytes reported in the log. **5. Export path.** Query 1 (rebuilt) → table in `social_employment_2` → `bq extract --destination_format PARQUET` to the bucket (wildcard file names, one file per shard) → `gsutil cp` (or `gcloud storage cp`) to `_data/rais_parquet/` locally → all further aggregation in R with `arrow::open_dataset()` or `duckdb`. The agent records the BD table's last-update date, the export date, row count, and byte size in a `_data/rais_parquet/README.md` so the snapshot is citable in the data description.

**6. Logging.** Every SQL string the agent executes is saved to `sql/` with a timestamped filename and the dry-run byte count in a header comment. The R scripts read the SQL from those files rather than embedding it, so the pipeline can be rerun without the agent.

**7. Revocation.** When the reform ends, Fernando runs `gcloud auth revoke` (user route) or deletes the service-account key in IAM (service-account route). Keys are not kept beyond the task.

**When to fall back to Route B.** Only if BigQuery access cannot be restored, or if BD's `microdados_vinculos` turns out to lack a column the reform needs (verify with `basedosdados::get_table_columns()` or `INFORMATION_SCHEMA.COLUMNS` first). The appendix at the end specifies Route B.

**R tooling.** `basedosdados` (CRAN; `get_table_columns()` for the schema, `bdplyr()` or `read_sql()` for extraction, `bd_write_csv()` to pull results; if it breaks after a `bigrquery`/`dbplyr` update, fall back to `bigrquery::bq_project_query()` with the same SQL instead of debugging the wrapper); `arrow` and `duckdb` for local aggregation; `deflateBR` to replace the hand-built IPCA deflator table (document the reference month). For the CNAE hierarchy, join to `basedosdados.br_bd_diretorios_brasil.cnae_2` and `cnae_1` rather than hand-coding sections; the 1.0-to-2.0 correspondence comes from IBGE/CONCLA.

1. **Public-sector definition (Task B).** Two candidate flags, both to be extracted; choose which is primary. (a) `natureza_juridica`: codes in the 1xx-x range are "Administração Pública" and cover public schools, hospitals, and autarquias that CNAE would classify under education or health. (b) CNAE division 84 (CNAE 2.0, 2006 onward) / division 75 (CNAE 1.0, before 2006): "administração pública, defesa e seguridade social". My prior: natureza jurídica as primary and CNAE 84/75 as the alternative, because in many interior municipalities the prefeitura is the only formal employer, and that includes its schools and health posts. Both flags are extracted so either definition can be used later. Verify the exact column names and code lists in the Base dos Dados schema before committing.
2. **Sector granularity (Task C).** CNAE 1.0 (until 2005) and CNAE 2.0 (2006 onward) do not map one-to-one below the section level. Proposal: extract both raw codes, aggregate at the section level (A–U in 2.0; letters in 1.0), and build a harmonized crosswalk only where a section-level match is exact. Division-level shares are a later refinement, not a first pass.
3. **Minimum-wage reference series (Task A).** Several wage statistics are expressed relative to the national minimum wage of the same year, and the nominal minimum wage changes mid-year in several years. 4. **Reliability floor (Tasks A and B).** Municipality-years with very few vínculos give unstable medians and shares. Proposal: report `n_vinculos` in every output and set the missing-value rule at ≥ 30 vínculos, to be applied downstream in script 02, not in SQL. Confirm the threshold.
5. **Scope of Task C.** Sectoral counts and shares are stored as such; derived measures that presuppose a particular design (weighted growth predictions, exposure indices, and the like) are not built in this reform. My prior: counts and shares only, so the data serve any later use without pre-committing to one.

## Task A — Municipal wage distribution

Purpose: the panel describes each municipality's formal wages only through six bracket counts anchored to the 2024 minimum wage. The full distribution (quantiles, means, and shares relative to the minimum wage in force each year) is more informative and can be summarized later in any way the analysis requires. Only bracket counts survived aggregation, so this has to be recomputed from the vínculo-level table.

1. Write a new aggregation query (Query 3) on `rais_vinculos_deflat` returning, by `year × geocode`: `n_vinculos`, median of `valor_remuneracao_media` (nominal), p10, p25, p75, mean, and the same statistics for the deflated wage. Use `APPROX_QUANTILES` or `PERCENTILE_CONT` as appropriate; check cost with a dry run first.
2. Build a small reference table `mw_nominal_annual` (year, nominal minimum wage under the convention chosen in 0.3, and the IPCA-deflated 2024 value). Source it from the official decrees and keep the citation in the script header.
3. Compute the ratio of the year's minimum wage to the municipal median wage, `mw_to_median = mw_nominal_t / median_wage_nominal_mt`, as a descriptive indicator of where the local wage distribution sits relative to the national floor (nominal on both sides, to avoid a double deflation error).
4. Compute shares of vínculos at or below multiples of the contemporaneous minimum wage: `<= 1.0 × mw_nominal_t`, `<= 1.2 × mw_nominal_t`, `<= 1.5 × mw_nominal_t`. These complement the existing brackets, which are fixed in real terms, with a series that follows the wage floor of each year.
5. Output: `_data/data_employment_rais_wages.csv`. Downstream: script 02 reads it and applies the reliability floor from 0.4; script 06 handles any normalization. Diagnostics to print: distributions of the median wage, `mw_to_median`, and the threshold shares by year and by state; correlation of the threshold shares with the existing `emp_share_low_workers`; count of municipality-years below the reliability floor.

Interpretation note for the data description: all wage statistics describe the formal sector only. In municipalities with a thin formal sector the median wage reflects a handful of employers, and Task B provides the disaggregation needed to read it.

## Task B — Sector and legal-nature codes, public/private disaggregation

Purpose: the existing employment variables describe the whole formal sector, public and private together. In interior municipalities where the prefeitura is essentially the only formal employer, wages cluster at or above the minimum and the labor-market picture is dominated by public payroll, so a low share of low-wage workers can coexist with deep household poverty. Separating public from private employment lets later analysis choose which population a given variable describes. The original extraction kept CBO but not sector or legal nature, so the fix must happen in Query 1.

1. Modify Query 1 to carry `cnae_1`, `cnae_2` (and the subclass column if present), and `natureza_juridica` into `rais_vinculos_deflat`. Verify the column names in the Base dos Dados schema; note which years populate each CNAE version. Rebuild the intermediate table and run the regression rule above.
2. Create `public_sector` (per decision 0.1) and `public_sector_cnae` (division 84/75) flags in the intermediate table.
3. Re-run Query 2 twice more: once restricted to `public_sector = 0`, once restricted to `public_sector_cnae = 0`. Output: `_data/data_employment_rais_private.csv` (and a `_cnae` variant), same layout as the current file, so script 02 can build `_priv` versions of every existing employment variable (`emp_pia_rate_*_priv`, `emp_share_*_priv`) with the same code path. Also store the public-sector count itself, `workers_public`, so the public share is a variable in its own right.
4. Re-run Task A's Query 3 on the private-sector subset, so all wage statistics exist in private-sector versions.
5. Diagnostics to print: public-sector share of vínculos by municipality-year (distribution by year and by state, the 20 municipalities with the highest shares); how many municipality-years fall below the reliability floor once the public sector is removed; a comparison of the whole-sector and private-sector versions of `emp_share_low_workers` (correlation, and the municipalities where they diverge most).

Downstream: the whole-sector variables stay as they are; the `_priv` variables and `workers_public` enter the panel alongside them. Which version an analysis uses is decided in that analysis, on conceptual grounds.

## Task C — Sectoral employment counts

Purpose: the panel has no sectoral composition of formal employment; the agricultural/non-agricultural split is occupational (CBO), not establishment-based. Sector counts by CNAE section give the composition of each municipality's formal economy and allow any later comparison with national or regional sector trends. This task stores counts and shares only (see decision 0.5).

1. New aggregation query (Query 4) on the rebuilt `rais_vinculos_deflat`: worker counts by `year × geocode × cnae_section_harmonized`, with the public-sector flag carried so the query can be filtered. Also produce the national counts by `year × cnae_section_harmonized` for all Brazil (a separate pass on the source table without the Legal Amazon state filter) and a version excluding the 9 Legal Amazon states, as reference series for any comparison of local against external sector trends.
2. Sector shares: municipal sector shares by year, and a 2000–2003 average as a convenient early-period summary. Flag municipality-years below the reliability floor.
3. Harmonize the 2005/2006 CNAE break at the section level. Document which sections could not be harmonized exactly and were dropped or merged.
4. Output: `_data/data_employment_rais_sector.csv` (municipal counts and shares by year), `_data/rais_sector_shares_2000_03.csv`, `_data/rais_sector_national.csv` (national and Legal-Amazon-excluded counts by year). No derived index is constructed in this task.
5. Diagnostics to print: share of employment in agriculture (CNAE section A) versus the CBO-based `workers_agricultural`; the two should be correlated but not identical (occupation versus establishment sector), and the gap is worth one sentence in the data description.

## Appendix — Route B: rebuild from the raw PDET microdata (fallback only)

Use this route only under the conditions stated in the route decision. It replaces the source, not the tasks: Tasks A, B and C are unchanged; what changes is how `rais_vinculos_deflat` gets built.

1. **Source and access.** Public non-identified RAIS Vínculos microdata are distributed by the MTE's PDET as annual .txt files compressed in .7z, one file per state and year through 2017 and per macro-region from 2018 (the Legal Amazon states fall in the Norte and Centro-Oeste files, plus Maranhão in Nordeste). Access is via the MTE FTP server. The agent should script the download with a retry loop, log every file's size and hash, and stop and report if the server refuses connections rather than switching to an unofficial mirror. Fernando confirms the mirror if one is needed.
2. **Storage and tooling.** Budget disk for the compressed files plus the extracted 9-state slice. Prefer the Python tool `pdet-data` (Quantilica, Polars-based) for download and parsing: it handles the FTP listing, the ragged CSVs, the encoding shifts and type conversion, and writes Parquet, which R then reads with `arrow`/`duckdb`. Do not use `microdadosBrasil` (coverage ends 2014, unmaintained) or the 2019-era FTP wrappers. If `pdet-data` cannot be used, extract with `7z` and read each file with `duckdb` (`read_csv` with explicit column types, `delim = ';'`, encoding `latin-1`), keep only the needed columns, filter to the 9 states, and write year-level Parquet. Never load a full-year file into R memory.
3. **Layout harmonization (the hard part).** Column names and order change across years; the agent must build a year-by-column crosswalk before parsing, from the PDET layout PDFs, and validate each year against a hand-checked sample of 1,000 rows. Specific traps: municipality code has 6 digits in the raw files (append the IBGE check digit or join on the 6-digit code to the IBGE table); `Vínculo Ativo 31/12` is the active-status flag; `Vl Remun Média Nom` is the nominal average monthly wage (also keep `Vl Remun Dezembro Nom`); `CNAE 95 Classe` carries CNAE 1.0 and `CNAE 2.0 Classe` and `CNAE 2.0 Subclasse` carry CNAE 2.0 (populated from 2006, with some retro-coding in later releases); `CBO Ocupação 2002` and `CBO 94 Ocupação` carry the two occupational codes; `Natureza Jurídica` is a 4-digit code following the CONCLA table. Confirm the exact header strings per year from the layouts, not from memory.
4. **Reproduce before extending.** Rebuild Query 2's output from the raw files and compare it cell by cell with the current `_data/data_employment_rais`. Discrepancies are expected at the margin (BD applies its own cleaning to wages and codes); the agent documents every difference above 1 percent of a municipality-year's worker count and stops for review. Only after this reconciliation does Route B produce the Task A–C outputs.
5. **Document the switch.** If Route B is used, the data description must say that the labor variables now come from the raw PDET microdata processed locally, cite the download date and file list, and explain the reconciliation with the earlier BD-based series.

Time estimate for an agent: Route A, one working session for extraction plus one for aggregation and diagnostics. Route B, several days, most of it in step 3, with a real risk of silent errors in the harmonization.
